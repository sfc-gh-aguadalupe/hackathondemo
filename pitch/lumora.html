Act II — The Agent

Four real tools, two honest placeholders

KPI & evidence BUILT

GET_LUMORA_KPIS — inventory exposure, forecast, error and bias, from deterministic SQL.

Forecast explanation BUILT

EXPLAIN_FORECAST_VARIANCE — leading drivers behind forecast vs. actuals, calculated not guessed.

Scenario simulation BUILT

RUN_DEMAND_SCENARIO — recalculates demand, exposure, and stockout risk under stated assumptions.

Policy & stakeholder search BUILT

Cortex Search over synthetic policy, residency, and architecture-review documents.

Forecast retraining request PRE-STAGED

Recorder procedure logs the request; routes to a prebuilt evaluation result rather than a live training run.

Fine-tuning request PRE-STAGED

Recorder captures approved feedback and returns a job status; the before/after comparison is pre-staged.

Honest badges, on purpose — pre-staged is labelled pre-staged.
Act III — The Storyline

The 8-minute CFO storyline

1 · The question

"Which part of the group's inventory position needs attention first, and why?"

2 · The investigation

Agent calls the KPI and explanation tools; shows what changed and which evidence supports it.

3 · The scenario

"What if the promotion lifts demand 12% for four weeks?" It removes only 3% of the exposure — so this is a markdown decision, not a promotional one.

4 · Cross-brand value

Brand-specific issue, or a group-level pattern? The shared foundation makes the answer visible.

5 · The governed AI moment

"Can we use EU customer data here?" — policy search grounds the answer and flags the control.

6 · The learning loop

A CFO correction becomes approved feedback, routed to two distinct improvement requests.

7 · The close

A bounded, funded first step — measured by forecast quality and decision speed, not a promise.

Act III — Improvement

Two loops. Never conflated.

Numeric forecast retraining

Refresh features → retrain or refit the demand model → evaluate → promote the better version. This changes the forecast.

LLM fine-tuning for explanations

Approved examples → prompt-completion training view → Cortex Fine-tuning job. This changes the agent's language, not the numbers.

Same feedback. Two different pipelines.
Act III — Governance

Trust, built in, not bolted on

  • Residency zone and sensitivity class on every record — present from the first row
  • Source system preserved — fragmentation stays visible, never silently merged away
  • Tool-backed answers only — the agent never invents a financial figure
  • Explicit assumptions — every scenario states what it assumed
  • Human decision point — pricing, inventory commitment, and customer treatment require a person
  • Deterministic calculations in SQL — not LLM opinion
Governance the CFO can see, not just trust.
